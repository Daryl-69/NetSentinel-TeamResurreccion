02 What we are actually looking for

One host. Four ordinary services. In order.

Every request below is to a legitimate, allow-listed domain. No signature fires on any single one. The sequence is the attack.

SENTRY · monitoring 6 hosts
benign traffic chain step escalated to Inspector
Step 1 · live now DEV-07 → Recon_API A query to a public code-search API. On its own: a developer looking something up. The Sentry only notes that this category is rare for this host at this hour.
Step 2 DEV-07 → Code_Repo A paste to a public gist. Allow-listed, TLS, no payload read. What moves the score is the transition Recon→Repo, which never appears in this host's commissioning profile.
Step 3 · threshold crossed DEV-07 → Messaging Steady outbound to a messaging API — the beacon. Its inter-arrival times are uniform; human traffic is log-normal. The Sentry now ranks this host-day inside the top 5% and escalates.
Step 4 DEV-07 → Cloud_Store A large upload to allow-listed cloud storage. Four ordinary services. Four separate allow-list hits. Nothing here trips a signature, a domain block or an EDR rule.
Escalation · back to the Inspector INSPECTOR re-runs Only on this host-day — not the other 99.9%. The big model reconstructs the ordered chain, returns the verdict, and the analyst gets one alert with four timestamped steps.
03 The cascade

Expensive eyes at commissioning. Cheap eyes always on.

PassiveNo agent, no DPI, no inline device. Headers only — 160-byte snaplen, no payload ever written to disk.
The splitThe Inspector is a graph autoencoder that learns "normal" unsupervised. The Sentry is 13.7× smaller and decides what deserves the Inspector.
Prior art, statedThe Inspector is GraphIDS-shaped (arXiv:2509.16625). The cascade and distillation are established. Ours is the cross-service sequence framing.
04 How the Inspector learns, and the data problem

No dataset exists for this. So we're building one.

Jitter-TrapA jittered beacon produces uniform inter-arrival times; humans are log-normal and bursty. The evasion is itself the signature.
The structural gapLANL has labels and no egress. WRCCDC has egress and one day. IoT-23 has labels and no hostnames. A 124-dataset survey found none with multi-stage campaigns.
Running nowSix laptops, 12 days, hourly rotation, ~113 MB/hour each. Live on stage — see slide 07.
05 The Sentry

A router, not a detector.

The reframeNot "can a small model detect?" but "can a small model decide what deserves a big model?" That is what makes it affordable on CPU-only OT hardware.
Why B lostDistillation transfer is asymmetric — local outliers move at only 20% (MDPI MAKE 8(3):60). So we distil the encoder, never the decision.
Say it precisely96.9% is agreement with the teacher — an efficiency number. It is never a detection rate.
06 Validation

The check that argued against us.

Global 0.745 → within-host 0.557Score each host against its own baseline and the signal vanishes. Attacked hosts run at 0.811 activity density vs 0.530 — the model ranked which host is unusual, not when.
Untested, not disprovenOf 749 red-team events, 119 destinations are modelled hosts but only 1 source is. We model outbound behaviour, so the side that matters was never measured.
What it buys usA tight confidence interval on a confounded metric is still confounded. We built this check, ran it on 3 seeds, and published the result that hurt.
07 Development — how we test our own instrument backup / Q&A only

We audit the capture, not just the model.

Most teams trust their capture and find out at the end. We wrote a tool that asks whether ours can actually feed the resolver — and it kept finding things. First that the snaplen was cutting every TLS handshake. Then, after we fixed that, that the fix still could not touch QUIC, which is most of our traffic. Both measured, both fixed, and the second fix turned a limitation into a capability.

capture_probe.py --dir D:\capture2026-09-11
  SNAPLEN -- read from the ORIGINAL on-wire length that pcapng records,
  so a capture that truncated a handshake still tells us how big it was.

    160  (5-10 Sep)   packets cut 50.8%    hostnames    0 of 442
    512  (10-11 Sep)  packets cut 25.1%    hostnames  365 of 415  (88.0%)

  THAT FIXED TLS. THEN WE MEASURED QUIC -- 61% OF OUR ENCRYPTED TRAFFIC.

    QUIC v1 Initial packets seen             805
    readable at snaplen 512                    0
    median Initial payload               1,230 B    RFC 9000 s14.1 pads
    larger than 512 B                      90.2%    Initials to >=1200 B

    >> 512 can NEVER name a QUIC flow. Not a tuning issue -- arithmetic.

  SO WE READ QUIC RATHER THAN SWITCHING IT OFF
    RFC 9001 s5.2: Initial keys derive from a PUBLISHED salt plus the
    client's own connection ID, in cleartext in the same packet. Reading
    the handshake is the documented design, not interception. We get the
    hostname and nothing else.  test_quic.py: 16/16 RFC vectors pass.

  WHAT NO SNAPLEN FIXES -- worth knowing before we claim coverage
    ClientHellos split across TCP segments  46.3%   needs TCP reassembly
    ClientHellos carrying Encrypted CH         43   visible name is a decoy

  RETRACTED: an earlier run of this tool reported "55% of DNS is DoH".
    It counted bootstrap lookups OF a resolver's own hostname. It did not
    mean what it said. Measured properly: 906 plaintext queries readable,
    106 distinct names, 1 connection to a known DoH endpoint.

    FIXED 2026-09-11  snaplen -> 0. Cost x1.84 bytes, ~1.01 GB/day,
    12.1 GB for 12 days against a 40 GB budget. The QUIC and DoH
    registry policies are no longer needed and have been dropped.
    Re-run this command any time -- it is the acceptance test.
Nothing errors when a capture is blinddumpcap writes happily, Zeek parses happily, and every destination just quietly lands in Unknown_External. There is no exception to catch. Only a tool that asks the right question finds it, so we built one and pointed it at ourselves.
It is an acceptance test nowcapture_probe.py runs against any capture folder and reports truncation, hostname coverage and QUIC readability. Every machine is checked against it before its data is used.
Same discipline, the demosinject_demo.py injects a chain into real traffic and a benign surge as a control. Until the surge stays quiet, we do not show it. A demo without a control proves nothing.
